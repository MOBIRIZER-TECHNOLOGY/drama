Katha, first full review

Code review and modernisation plan

Four independent reviews of the Phase 1 codebase, what was fixed the same day, what was handed to each app build, and what is deliberately left for the next phases.

Summary

Solid core, sharp edges. No exploitable path from the public internet remained after the same-day fixes.

What the reviewers agreed on. The ledger, unlock and webhook-only purchase design is right and consistently applied. The clients are typed end to end, have loading, empty and error states everywhere, and hold to the "no media URL except from play" rule. The weaknesses were at the edges: an unverifiable ad-unlock path, a non-terminal purchase state, sync SDK calls on the async loop, tokens stored where scripts can read them, native dialog and player lifecycle details, and release configuration still carrying template assets.

How the fixes were done. All 30 API and worker findings were applied directly, with regression tests. The admin panel's 25, the web app's 28 and the mobile app's 30 findings were fixed in their respective builds and verified with typecheck, lint and, for the Next.js apps, a build. The deferred items are architectural and listed in the roadmap with effort. Mobile items that need your Google, Apple and domain credentials are listed under release.

Web app

28 findings, no criticals. Every high, medium and low was fixed and verified with typecheck, lint, build and a runtime check of the headers, redirects and fonts.

  • Highs: series page seeded from the anonymous render and never refreshed after sign-in; no security headers or CSP; native dialog could desync and become impossible to reopen.
  • Mediums: multi-tab refresh race signing out every tab, stale closure downgrading a signed-in user on a transient error, image optimiser open to any host, user-typed avatar URLs crashing the page, CMS HTML injected unsanitised (now sanitised by the API on save and at render), progress not flushed on tab close, duplicate fetches per request, everything force-dynamic, hero carousel loading eight full images, a grant fetch that could strand an episode, invisible controls in the tab order, Latin-only font subsets for a Hindi-first product.

  • Deferred: BFF with httpOnly cookies, "use cache" with tag revalidation, query layer, Server Actions, player hook extraction with Media Session, Playwright coverage for the money paths.

Modernisation roadmap

The architectural recommendations all four reviewers converged on, ordered by what they unlock. Effort is for one engineer.

1. Server-held sessions (BFF) for web and admin L

  • Route handlers hold Katha tokens in httpOnly cookies; server components fetch personalised data; no token in localStorage.
  • Removes a whole class of findings: anonymous SSR seeding, multi-tab refresh races, XSS blast radius, client-only role gating.

2. Edge-enforced media signing M

  • CloudFront signed cookies, Bunny token auth, or an nginx verifier in front of MinIO using the media signing key.
  • Private prefixes for uploads and HLS; public prefix for covers and avatars. The single item that blocks charging money.

3. Query layer in all three apps M

  • TanStack Query v5 with an AsyncStorage persister on mobile: caching, dedupe, focus refetch, invalidation after mutations, offline home and series.
  • Replaces three hand-rolled loaders and about a dozen polling and optimistic patterns.

4. Next 16 caching and React 19 forms M

  • "use cache" with cacheTag on catalogue fetchers and a revalidate hook the API calls on publish.
  • useActionState and useOptimistic for forms and toggles once sessions are server-held.

5. One player pool and UI-thread chrome on mobile M

  • A single provider-owned pool driven by syncWindow, pinned current player, time updates only where needed.
  • Reanimated shared values for position and scrub, gestures via RNGH, useEventListener.

6. Observability and release engineering S

  • OpenTelemetry and Sentry across API, worker and apps; structured logs with request ids are already in.
  • EAS profiles and app.config.ts per environment; Playwright and Detox smoke tests on the money paths.

Before the first release

Items that need your accounts or assets, in the order they block.

  1. Docker Desktop locally, then migrate, seed and run the database tests that have only run in CI configuration.
  2. Media edge. Pick CloudFront, Bunny or the nginx verifier and set the production signing mode. Until then production refuses to boot by design.
  3. Brand assets. Real icons and splash replace the generated placeholders; fonts are bundled.
  4. Store accounts. App Store Connect and Play Console apps for com.mobirizer.katha, EAS project and credentials, Google OAuth clients with the signing fingerprints, Sign in with Apple, universal link files at katha.app.
  5. Gateways. Stripe and Razorpay webhook endpoints and secrets; RevenueCat for the stores in phase 2.
  6. Pin model ids and run a re-embed of the catalogue once the embedding model is final.
  7. Content. Nothing plays until real episodes are uploaded; a synthetic test-clip script is available on request for development.
