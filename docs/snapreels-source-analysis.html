Deployment

2. Web architecture

One Next.js App Router project serves the public site, the admin panel and the REST routes the Android app consumes.

Request flow

  • Middleware src/middleware.ts: fetches the admin-configured default locale from /api/default-locale with a 10-second in-memory cache, rewrites /foo to /{default}/foo internally, redirects /{default}/foo back to /foo, and honours a userLocale cookie. Returns 403 for direct hits to /uploads/videos/*. Rewrites any /{20+ chars}.txt to the IndexNow key route. Regex-checks the admin cookie shape on /admin.
  • Locale layout src/app/[lang]/layout.tsx: validates the locale, redirects to /install when the settings.admin document is missing, then mounts the provider tree, the OneSignal initialiser and a GA4 tracker.
  • Provider tree src/components/app-providers.tsx: FirebaseClientProvider, TranslationProvider, SettingsProvider, FavoritesProvider, WatchHistoryProvider. The wrapper renders nothing until Firebase auth resolves, so every public page is blank for the first paint. A dir attribute on a div is the only RTL handling. Disabled users see a blocked screen except on /contact and /p/*.
  • Data access: client components call server actions in src/lib/actions/*.ts and readers in src/lib/data.actions.ts directly. There is no REST layer for the web. The routes under src/app/api/ exist for the Android app, the profile fetch, uploads, video streaming and a few utilities.
  • Mongo client src/lib/mongodb.ts: lazy cached connection through getDb(). The default export also instantiates a second unconnected client at import time. The admin dashboard page opens its own client per request instead of using the shared one.
  • Demo mode src/lib/demo-mode.ts: DEMO_MODE=true blocks admin mutations and uploads with a fixed message. User-facing actions such as unlock, check-in and purchase are not blocked.

5. Payments

Five channels, no webhooks anywhere. Verification is triggered by the client after redirect.

Checkout

createCheckoutSessionAction(userId, packId, gateway) in payment.ts:181-216 builds a hosted checkout URL:

  • Stripe: Checkout Session, mode: 'payment', card only, amount price × 100 in settings.monetization.currency lower-cased (default usd).
  • PayPal: Orders v2; sandbox if the client id starts with sb- or contains sandbox.
  • Razorpay: a Payment Link, not Orders plus Checkout.js.
  • Flutterwave: v3 payments endpoint.
  • Google Play: handled on device, gateway id gplay at verification time.

Success URL is {siteUrl}/wallet?status=success&pack_id=…&gateway=…. The wallet page reads session_id, razorpay_payment_id, transaction_id or tx_ref, or token from the URL and calls verifyAndExecutePurchaseAction (wallet/page.tsx:158-173).

Verification

payment.ts:376-454 dedupes on purchases.sessionId, then per gateway: Stripe sessions.retrieve requires payment_status === 'paid' and amount_total / 100 ≈ price; PayPal fetches the order and captures if APPROVED with no amount check; Razorpay payments.fetch requires captured and matching amount; Flutterwave accepts any amount at or above 95 percent of the price; Google Play calls purchases.products.get with a hand-rolled RS256 service-account JWT (payment.ts:318-343) and requires purchaseState === 0. On success it increments coins or sets VIP and inserts transaction and purchase rows.

Nothing binds the session to the user or the pack. Two packs at the same price are interchangeable, and any account can redeem another account's paid session id once. Google Play purchases are never acknowledged or consumed, subscriptions are verified against the products endpoint, and the Android app sends orderId where the server expects the purchase token.

The mobile /checkout and /verify-purchase routes wrap the same actions behind the shared API key and take userId from the body.

6. Video delivery

Uploads, an encrypted URL token, and a Node proxy that streams both local and remote files.

Storage

settings.storage.activeProvider is one of local, s3, digitalocean, gcs (via HMAC S3 compatibility), backblaze, bunny. The upload route (api/upload/route.ts) requires the admin cookie session, sniffs magic bytes for png, jpg, gif, webp, mp4, webm, m3u8 and ts, caps images at 10 MB and videos at 2 GB, and writes to public/uploads/{images|videos}, an S3 PutObject with public-read ACL (falls back without ACL), or the Bunny Storage API. Cloud objects are public URLs. Episodes can also carry any arbitrary https URL or an iframe embed string typed into the admin.

Signed URL

getSecureVideoUrl(path) (content.ts:559-585) encrypts "{path}|{timeKey}" with AES-256-CBC (crypto.ts) using a secret auto-generated into settings.video-security (video-secret.ts:19) and returns /api/video?v={iv:hex}. The time key rotates per plugins.videoRotationPeriod (1h, 12h, 24h, 1w, 1mo; default 24h). Tokens are not per user or per IP and carry no MAC. Any URL containing .m3u8 is returned unchanged and never proxied.

Proxy

api/video/route.ts decrypts, accepts the current or previous time window unless videoProtectionEnabled is false, then either streams the local file by basename from public/uploads/videos/ with full Range support (206, 416, suffix ranges, 1 MB chunks) or fetches the remote URL server-side, forwarding Range and ETag with a spoofed Chrome user agent and referer, setting Access-Control-Allow-Origin: * and Cache-Control: public, max-age=86400. Cloud video therefore transits the Node process twice.

Exposure

  • The series page precomputes signed URLs for every episode and quality at render (data.ts:71-79), so a logged-out visitor receives playable links for locked episodes in the server payload.
  • The mobile episodes endpoint returns videoUrl for every episode regardless of unlock state (episodes/route.ts:52-68).
  • The series page passes the raw first-episode URL as initialVideoUrl, so remote sources for episode 1 bypass the proxy entirely.
  • Local files are addressable by basename once any token for the rotation window is known. Remote cloud URLs remain publicly fetchable.
  • No transcoding, no ABR ladder, no DRM, no referer check, no per-user binding.

7. Authentication

Firebase for end users, a single encrypted-cookie account for the admin, a static key for the app.

End users

  • Providers in components/auth-dialog.tsx:165-239: email and password, Google, Facebook, Apple (OAuthProvider('apple.com')), phone with an invisible RecaptchaVerifier. Each is toggled by a settings.general.*LoginEnabled flag.
  • Firebase web config comes from settings with a hard-coded fallback to the vendor's tiksnap-pro project in src/firebase/config.ts:1-8.
  • On auth state change, src/firebase/provider.tsx:64-101 GETs /api/user/{uid} with a Bearer ID token and POSTs /api/user/create on 404. The Mongo _id is the Firebase uid.
  • Server-side token verification calls Google Identity Toolkit accounts:lookup with the web API key (api/user/[uid]/route.ts:42-58) instead of verifying the signature with firebase-admin.
  • Password reset uses firebase-admin generatePasswordResetLink plus nodemailer, rate-limited per IP per day. Phone-only users get a generated {8 digits}@snapreels.com email.
  • Blocked users are enforced only client-side in app-providers.tsx:40. No device or session tracking exists.

Admin

  • One record in settings.admin with PBKDF2-SHA512 and an automatic upgrade from legacy SHA-256 (crypto.ts:42).
  • Login (auth.ts:60-70) sets an auth cookie containing AES-encrypted JSON {auth: true, user, createdAt} using the same secret as the video URLs, valid 7 days. Rotating the video secret logs the admin out.
  • Per-IP daily rate limits: failed logins (default 5) and password resets (default 3) in rate_limits.
  • verifyAdminSession is called by the upload route, the test-mail route and the admin layout. Admin server actions do not call it; they rely on the middleware cookie-shape check that protects only page navigation.
  • No roles, no second admin, no 2FA, no username re-check on session verification.

Mobile

Admin generates snap_apk_{48 hex} (content.ts:908) into settings.mobile.apiKey. The app hard-codes it in data/AppConfig.kt:9-10 and sends it as X-API-Key. Routes accept the key from the header or a ?apiKey= query string. Only some user routes additionally require a Firebase ID token. See section 10.

8. Public web journey

What a visitor actually gets, page by page.

  • Home app/[lang]/page.tsx: Embla autoplay hero of featured series with a blurred backdrop and Watch Now; Continue Watching (client-side, fetches all series and joins with history); Top Picks (12); one carousel per homepage category filtered client-side from the full list; a grid of everything; PWA install card if enabled.
  • Browse: /series groups everything by category; /category/[slug] is a grid. Neither page loads translations, so they are English only. Search (Ctrl/Cmd+K) downloads the catalogue and filters with title.includes().
  • Series detail components/series-detail-view.tsx (about 1,100 lines): portrait player on the left, info and episode grid on the right, similar series below, likes, bookmark, native share, report dialog, episode pagination by settings.episodesPerPage (default 15). Lock state is free, VIP or in the unlocked set; only the next sequential episode can be unlocked.
  • Unlock dialog: coins, or an admin-pasted ad script rendered in a srcDoc iframe with allow-same-origin allow-scripts and a countdown, then Skip and Unlock. Daily ad limit checked in the dialog only.
  • Wallet: packs and memberships, a redesigned vertical list of gateways with logos, Continue Payment, then redirect. History page is a paginated transaction table.
  • Rewards: 7-day streak strip with Claim Today's Bonus; task list with Go (opens link, timer, Claim) or Watch (iframe ad, timer, Claim).
  • Profile: display name, avatar resized client-side to 256 px and uploaded, PATCH with ID token, password change with re-auth.
  • My List: favourites tab and history tab with remove and clear. Contact: form with optional reCAPTCHA into the admin mailbox. CMS /p/[slug]: HTML from Mongo via dangerouslySetInnerHTML, translated per language key.
  • Theme: hard-coded dark. <html lang="en" class="dark"> on every locale, no toggle. RTL list ar, fa, he, ur is duplicated in two files and only sets dir; Tailwind ml-* and left-* classes are not mirrored.
  • Push: legacy OneSignal v15 web SDK with a slide-down prompt after a configurable delay.

9. Web player

react-player wrapped in a custom control layer.

  • react-player/lazy with config.file.forceVideo: true and controlsList: nodownload. Custom overlay: Radix slider with buffered value, volume, hold right half for 2x, hold left half to rewind with seekTo every 250 ms, fullscreen, quality dropdown when more than one source.
  • Source detection order: raw <iframe> string renders as an embed (controls, progress and autoplay-next disabled); Dailymotion page URLs are converted to iframes; .m3u8 loads hls.js from CDN and bypasses the proxy; local and https files go through the signed proxy. Because the file player is forced, bare YouTube or Vimeo page URLs do not work and must be entered as iframe embeds.
  • After 3 seconds of playback it fetches the first 5 MB of the next episode with a Range request as a warm-up.
  • onEnded navigates to the next episode; an end overlay shows two similar series when there is none. Unmuted autoplay failure falls back to muted.
  • Watch history is written every 30 seconds as a percentage, but resume only restores the episode via ?ep=N, never the timestamp.
  • src/app/layout.tsx monkey-patches Node.prototype.removeChild and insertBefore globally to swallow "child of a different parent" errors caused by embeds and translation extensions.

11. Android app

Native Kotlin, single activity, one view model, Compose screens.

Structure

  • Package com.example, applicationId com.snapreels.devsnaplix, versionCode 6, minSdk 24, targetSdk 36, release build not minified, debug keystore committed, release signing from environment variables.
  • MainActivity.kt gates on a connection check (branded splash with Retry), then a force-update check, then a NavHost with routes onboarding, login, home, detail, player, rewards, topup. No route arguments; selection is passed through view-model state. SplashScreen.kt is not in the graph.
  • viewmodel/SnapReelsViewModel.kt is a 754-line god object. data/SnapReelsRepository.kt does OkHttp calls with hand-written org.json parsing and shows Toasts from the repository layer.
  • Room database v4 with destructive migration: user_profiles keyed by email (coins, VIP, streak, todayAdCount), favorite_dramas, unlocked_episodes keyed by dramaId_episodeNumber. A user-state cache only; series and episodes are always fetched live.
  • Locale is applied in attachBaseContext from a language_code preference with the deprecated updateConfiguration. The onboarding language picker is fed by the server languages list.

  • Ads (data/AdsManager.kt): AdMob, AppLovin MAX and FAN all initialised. Provider admob, applovin or facebook, or multi which round-robins per ad type across enabled providers with no fallback on load failure. Banner on Home, interstitial on player exit, rewarded for unlock and tasks, reward attested by the client. The manifest APPLICATION_ID is Google's test app id and the admobAppId setting is never applied.
  • Coin sync: balance is whatever GET /api/user returns, cached in Room. Local award paths (awardCoins, awardVip, purchaseCoins, purchaseVip) PATCH fields the server ignores and are effectively dead.

Other

  • data/GeminiService.kt calls generativelanguage.googleapis.com directly with a query-string key that is set to an empty string, so it always returns canned fallback metadata. No screen calls it. metadata.json and README.md are AI Studio boilerplate.
  • Rewards: check-in through the API; ad tasks through a rewarded ad then claim; link tasks open the URL and run a wall-clock countdown (default 5 s) that is trivially bypassable.
  • Share is a plain ACTION_SEND with {siteUrl}/series/{slug}?ep=N and a fallback host of snapreels.app. No deep-link intent filters, no referral.
  • Remote config supports force update (block screen with the update URL when versionCode is behind) but no maintenance flag, no global ads kill switch, no announcements.
  • Strings: default 222 keys, translations 205 to 213 keys each, uniform structure that indicates machine generation. No server-driven strings.
  • usesCleartextTraffic="true", allowBackup="true", and google-services.json for the vendor's project ships in the bundle.
  • Tests: 2+2, app name, one Roborazzi screenshot. The instrumented test asserts package com.example, which does not match the application id.

14. AI features

Two systems exist in the tree. One is used.

Used: callAi in src/lib/actions/ai.ts

  • Provider from settings.plugins.aiProvider: Groq llama-3.3-70b-versatile at temperature 0.1 in JSON mode (default), OpenAI gpt-4o-mini, Gemini through @google/generative-ai with model id gemini-3.5-flash, which the test-key action also uses.
  • generateFullSeriesMetadataAction(prompt): one JSON response with title, description, genres, tags, seoTitle, metaDescription, metaKeywords and slug, poured into the series form.
  • translateLanguageAction (content.ts:264): builds one prompt containing all 177 English UI keys plus every CMS page title and HTML, asks for one JSON blob, parses, upserts translations/{code}, revalidates. Single shot; the error text suggests switching to Gemini when output is truncated.

Unused: Genkit flows in src/ai

genkit.ts configures @genkit-ai/google-genai with googleai/gemini-1.5-flash. Three flows exist: generate-series-categories (title and description to up to 5 categories and 5 to 10 tags), generate-series-seo (title and description to seoTitle under 60 chars, metaDescription under 160, 5 to 7 keywords), translate-ui (language name to a key map, embedding the whole English dictionary in the prompt). Nothing imports them except src/ai/dev.ts.

The Android GeminiService described in section 11 is a third, also unused, path.

15. Localisation

  • src/lib/language-list.ts lists 103 entries (en, en-GB, ar, fr, fr-CA, and so on to zu). i18n.locales is all of them; the effective default comes from settings.defaultLanguageCode through middleware and a client-side window.location.replace.
  • The switcher shows only languages the admin has added; flags come from flagcdn.com.
  • 177 keys in src/lib/translation-keys.ts with placeholders such as {episodeNumber}. Stored as one document per language. Loaded server-side for metadata and the home page, then again client-side on every locale change, so client text flashes English first.
  • Translated: home, locale layout, CMS pages, client components. Not translated: /series, /category, wallet history, the 404 page, and strings inside the series detail view such as Synopsis, Share, Saved.
  • Content visibility per language uses series.targetLanguages and the ?lang= filter; there are no translated titles or synopses.
  • Android ships its own static string files (section 11) and ignores the server translations.

16. SEO, PWA, install and licence

SEO

  • Root metadata from general settings; locale layout and home override with translated seo_* keys; series pages use their own SEO fields; CMS pages use the translated title.
  • No OpenGraph, Twitter cards, canonical, hreflang or JSON-LD anywhere in the public app.
  • Sitemap (force-dynamic): home, contact, wallet and profile (both auth-only), every series by slug or id, every CMS page, default locale only, lastmod always now, base URL falls back to example.com.
  • robots.txt is admin text or a permissive default; ads.txt is the ads document; IndexNow key is written to public/{key}.txt and also served dynamically; series save pings Bing.
  • next.config.ts ignores TypeScript and ESLint errors at build, allows images from any https host, and sets the server-action body limit to 2 GB.

PWA

public/sw.js is skipWaiting, clients.claim and an empty fetch handler with a comment to add caching later. No offline support, no push handling. The dynamic manifest points every icon at the favicon with declared 192 and 512 sizes; a stale public/manifest.json still references picsum.photos icons. The install card is a custom beforeinstallprompt handler with dismissal remembered in sessionStorage.

Install wizard

Five steps: Envato purchase code and domain; Mongo connection test (the URI must already be in .env); seed with a fake four-second progress bar; site name and URL; admin username, email and password. Installed means the settings.admin document exists. Firebase configuration is entered later in the admin.

Licence

  • Activation POSTs {purchaseCode, domain} to DEVSNAPLIX_API_URL, default https://devsnaplix-api.gadohost.com/api/verify, and stores the result in general settings.
  • verifyLicensePeriodically (data.actions.ts:399-497) runs from the admin layout every 24 hours. Invalid means isLicenseActive=false and a redirect to /activate; a network failure retries in 4 hours and lets the admin through; a missing purchase code blocks.
  • Only /admin is gated. The public site, API and video streams never check. LicenseActivationPrompt exists but is not mounted.

18. Bugs and dead code

Functional bugs

  • Performance and PWA settings page cannot save; its keys are missing from the allowlist.
  • Google Play: wrong token field sent, no acknowledge or consume, subscriptions verified as products. Real purchases would refund.
  • WebView checkout shows Success regardless of verification; session id defaults to WEB_DIRECT; non-Stripe return URLs are not parsed correctly.
  • Android cannot play HLS; the backend has passed m3u8 through unproxied since 1.1.5.
  • Gemini model id gemini-3.5-flash is used for both generation and the key test.
  • Two like collections disagree between web and mobile.
  • Default free episode count differs across web (0), mobile (3) and the admin form (5); default price differs across web (50) and mobile (10).
  • Facebook and Apple login are stubs on Android; the Android app has no push SDK despite the documentation.
  • /series and /category pages are never translated; <html lang> is always en.
  • Every listing, search, favourites and history view downloads the entire catalogue; the admin user list downloads every user.
  • Mobile series endpoint runs one count query per series; Shorts fetches every series' episodes on each refresh.
  • Dashboard opens its own Mongo client per request; health card and two metrics are decorative.

Dead code and leftovers

  • Firestore client init, useDoc and useCollection hooks (used only by the profile rewards flag, which reads a document nothing writes, and the unlinked licence page), firestore.rules, docs/backend.json, server-init.ts, non-blocking-updates.tsx, FirebaseErrorListener.
  • Genkit flows and src/ai/dev.ts; apphosting.yaml; studio.json; public/manifest.json; middleware.ts.unused.
  • LicenseActivationPrompt, mobile-preview page, Trending page, API settings tombstone, iOS tabs, the unrouted improved episodes page, geoip.ts, the tracking stub.
  • Android: SplashScreen.kt, GeminiService.kt and its view-model state, awardCoins and friends, DummyData, Test.java, GlobalScope import, Retrofit and Moshi dependencies.
  • Documentation is honest about its GadoHost affiliation and includes a WhatsApp support link; the admin guide file is mistitled "Android App Setup".
